# Tesseract project folders

## Channel context

Use the user's channel profile and actual source asset. For Ship Sh!t Show, read [the bundled profile](references/channel-profile.md); viewers using another channel should provide their audience, voice, formats, links and visual references. A profile is context, not permission to publish, upload footage, buy generation or contact a partner.

Inspect the existing workspace before introducing a new structure. Preserve referenced media/native project paths. For a new library use [the folder contract](references/folders.md); an existing library can map its current folders to that contract without relocating recordings.

Read the installed Tesseract plugin's video/editor guidance for actual operations. Verify its supported CLI/tool version before editing. Do not copy a stale plugin schema into this skill or assume API names. If Tesseract is unavailable, prepare the folder/edit brief and report the limitation rather than substituting a new editing product.

Separate immutable source media/transcripts, current work, meaningful version snapshots and reviewed final media. Use an episode recording-date key plus a slug when needed. Store the source YouTube ID and published derivative IDs in project metadata. A recap published on another date still belongs to the source recording project.

Promote only an identified version after structural checks, export metadata, playback/listening review and any required edit/source comparison. Record which checks were actually performed. Preserve mastering recipes when exported media differs from the native render. Do not overwrite an approved final without an explicit replacement/version trail. Do not auto-delete large native archives or duplicate all embedded media into Git.

Public handoff goes to the archive: text, captions, cuts, description context, metadata and links. Local media stays local. A folder task does not authorize rendering charges, media upload, account changes or Git initialization of an existing local-only workspace.
