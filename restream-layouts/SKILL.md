# Restream production layouts

## Channel context

Use the user's channel profile and actual source asset. For Ship Sh!t Show, read [the bundled profile](references/channel-profile.md); viewers using another channel should provide their audience, voice, formats, links and visual references. A profile is context, not permission to publish, upload footage, buy generation or contact a partner.

Start with the actual Studio canvas, host count, source dimensions, captions, existing theme/plan and intended scenes. Inspect the UI or supplied screenshot when placing exact camera windows; do not guess their coordinates. Use native Studio layouts/name controls where they solve the job.

Prepare a scene map: host discussion, readable screen demo, optional partner segment, starting/ending or break scene. Create only the needed background, transparent overlay, logo and motion assets. Keep camera windows transparent in overlays, leave caption/nameplate clearance, and prioritize product-screen legibility over decoration. Reuse the brand system without covering every scene in thumbnail-sized text.

Recheck [Restream graphics requirements](https://support.restream.io/en/articles/8540835-add-graphics-to-your-stream-in-studio). Current reference: 1920×1080 overlays (up to 25 MB), 1920×1080 backgrounds (up to 150 MB for video, under 30 seconds), recommended 512×512 logo; custom graphics require an eligible paid plan. Video uploaded as a graphic does not play its audio: use the appropriate clip/media source for an audible intro.

For generation use an available image tool; for editable compositions/motion use the installed editor/plugin. Return separate labelled assets, scene instructions and a manifest of sizes/duration/transparency. Test in the actual Studio at broadcast size: host crops, screen readability, spelling, caption clearance and transitions. Mark checks unavailable without pretending an image generation proves layout fit. Drafting assets does not authorize changing a live stream or upgrading a plan.
