# Find channel-fit stories

## Channel context

Use the user's channel profile and actual source asset. For Ship Sh!t Show, read [the bundled profile](references/channel-profile.md); viewers using another channel should provide their audience, voice, formats, links and visual references. A profile is context, not permission to publish, upload footage, buy generation or contact a partner.

Start with the audience decision, publication date and hosts' experience. Browse current primary sources for releases, pricing, benchmarks and policy claims; use X and other communities to surface useful questions and disagreement. Search platforms because they add evidence, not because every brief must contain Reddit, Hacker News, YouTube and X.

For each candidate, report what changed, event/publication dates, source links, audience consequence, available firsthand proof, uncertainty and format fit. Avoid quoting community sentiment as representative data. Model comparisons need workload, version, cost/usage and workflow context; vendor leaderboards do not establish the hosts' results.

Rank by audience usefulness, credible evidence, host experience and production readiness. Explain any numerical scoring rubric rather than invent precision. Mark a proposed demo unavailable if quota/fixture is missing, and suggest a recorded/local fallback only when it exists or can be prepared within authorization.

Return a compact shortlist with a recommended viewer question and source cluster for the strongest story. Link to the show-prep skill when available; otherwise include the minimal segment cues directly. Do not generate a full script or force an unrelated build around a news item.
